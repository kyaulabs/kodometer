# 🚀 Kodometer 0.3.0

## ✨ Highlights

Kodometer 0.3.0 brings the Soft Iris identity, recognizable provider icons, and optional donut-style panel meters to the native Plasma widget. Codex subscription names now omit hard-coded prices.

This is a minor release from 0.2.1: the `feat(ui)` commit adds user-visible presentation options, while subsequent `fix` commits refine labels and validation. There are no declared breaking changes, credential migrations, or changes to selected-only provider polling. Existing widgets keep bars by default.

## 🚀 Features

- **Soft Iris branding:** the widget browser and notifications use the new application icon. The popup has light/dark wordmarks and theme-aware symbolic artwork. Controls, surfaces, text, focus, and status messages still follow your desktop theme.
- **Actual provider artwork:** all eight providers have their supplied SVG icons in tabs, overview cards, and detail headers. Non-square artwork is centered on square canvases without stretching. Tab icon canvases increase from Kirigami's small to small-medium size, normally 16 to 22 logical pixels.
- **Optional panel donuts:** open **Configure Kodometer… → General → Panel meters → Donut charts**. Session and weekly remaining quotas appear side by side on horizontal panels and stacked on vertical panels. Percentages appear inside when space permits; tooltips identify each quota. Unavailable values say **Not reported**, rather than appearing as a reported zero.
- **Selectable meter accent:** **Kodometer Iris** is the default, with Iris on dark surfaces and Deep Iris on light surfaces. Choose **Desktop accent** to follow Plasma's highlight color instead. Chart and accent choices are per widget and follow Apply, Cancel, and Defaults. Popup quota rows remain bars.

The complete brand pack, including website assets, is retained in the source tree. Plasma loads only its runtime SVG subset; no website deployment or font installation is added.

## 🐛 Fixes

- Codex displays **Pro** and **Pro-Lite** without selectively attaching subscription prices. API-reported tier distinctions and plan-name normalization are preserved.
- Compact meters handle non-finite and out-of-range input defensively. Missing quota remains distinguishable from a genuine zero in text and accessibility descriptions.
- Asset checks preserve the supplied archive bytes and validate square canvases. Secret scanning recognizes only the exact known palette-checksum row that previously resembled an API token; unrelated keys in the same file remain detectable.

Codex banked resets remain a read-only count. This release adds no reset-consumption button or redemption request.

| Arch Linux (rolling), native package | x86_64 | `kodometer-0.3.0-1-x86_64.pkg.tar.zst` |

| Arch Linux (rolling), legacy binary archive | x86_64 | `kodometer-0.3.0-linux-x86_64.tar.gz` |

Each of these seven payloads has an individual `.sha256` sidecar. `kodometer-0.3.0-SHA256SUMS` lists all seven payloads, for 15 uploaded assets in total. Use the named source archive for the verified release/AUR build chain, not GitHub's separately generated **Source code** downloads.

AUR recipes are included, but automatic AUR publication remains unconfigured and disabled for this release. Recipe availability is not a claim that a live AUR entry exists. The legacy binary archive is built on Arch; it is not a portable replacement for the Ubuntu or Fedora packages.

## 🛠️ Installation and upgrade

Download the matching package and its checksum from this release. Before running an install command, log out of Plasma so the plugin is no longer loaded; install from a TTY or SSH session and log back in afterward. Run only the pair of commands for your distribution:

```bash
# Arch Linux
sha256sum -c kodometer-0.3.0-1-x86_64.pkg.tar.zst.sha256
sudo pacman -U ./kodometer-0.3.0-1-x86_64.pkg.tar.zst

# Ubuntu 26.04 LTS
sha256sum -c kodometer_0.3.0-1ubuntu26.04_amd64.deb.sha256
sudo apt install ./kodometer_0.3.0-1ubuntu26.04_amd64.deb

# Fedora 43
sha256sum -c kodometer-0.3.0-1.fc43.x86_64.rpm.sha256
sudo dnf install ./kodometer-0.3.0-1.fc43.x86_64.rpm

# Fedora 44
sha256sum -c kodometer-0.3.0-1.fc44.x86_64.rpm.sha256
sudo dnf install ./kodometer-0.3.0-1.fc44.x86_64.rpm
```

Keep the same installation method and prefix; remove duplicate manual system/user-local copies before switching to a managed package. The applet ID remains `org.kyaulabs.kodometer`.

Preferences, OAuth files, and KWallet entries need no migration and are not removed. Manual installations now include the application icon as well as the plugin, notification configuration, license, and README; use the generated install manifest for removal. See the [native package guide](https://github.com/kyaulabs/kodometer/blob/v0.3.0/docs/packaging.md) and [source/user-local installation instructions](https://github.com/kyaulabs/kodometer/blob/v0.3.0/README.md#build-and-install).

## ⚠️ Compatibility and known limitations

- Requires **KDE Plasma/libplasma 6.4+**, Qt 6.4+, and the documented KDE Wallet/notification dependencies. Wayland and X11 remain supported.
- Supported binary targets remain Arch Linux, Ubuntu 26.04 LTS, and Fedora 43/44 on x64. Ubuntu 24.04, ARM binaries, generic Debian/RHEL compatibility, and hosted APT/DNF repositories are not included. Dependencies are not bundled, and each distribution builds against its own libraries.
- Provider scope is unchanged. Gemini API-key/Vertex authentication and retired consumer tiers do not provide Code Assist OAuth quota support. Kimi Code's website **Total usage** lane remains unsupported. OpenRouter Management Activity still needs its separate Management key; xAI covers developer billing, not Grok subscriptions. See the [provider requirements](https://github.com/kyaulabs/kodometer/blob/v0.3.0/README.md#requirements).
- Small panels may not have room for donut-center text; tooltips retain the values. Appearance on arbitrary custom or translucent themes is not guaranteed by the supplied brand colors. Desktop-accent mode is available if it better matches your panel.

## 🔒 Security and privacy

No provider CLI execution, browser-cookie access, new billing requests, or credential copying is introduced. Manually entered credentials and private selectors remain in KWallet. Named profiles/accounts remain exclusive and selected-only; OAuth renewal stays with its originating credential file. The new display settings contain no secrets.

Checksums detect corruption, not publisher identity. Release tags are annotated but are not independently GPG-signed by the publication workflow; DEB/RPM artifacts are not independently signed either. Published assets are immutable. Packaging does not delete user credentials or preferences. See [security and privacy](https://github.com/kyaulabs/kodometer/blob/v0.3.0/README.md#security-and-privacy) for the full contract.

## ✅ Validation

Publication is gated on native Debug tests, fresh Release-mode builds for all four distributions, and separate clean-runtime install/reinstall/launch checks without development dependencies. Automated checks cover compiled asset URLs, SVG loading and canvas normalization, configuration persistence, quota rendering, provider behavior, source formatting, QML lint, release automation, workflow/commit conventions, dependency review, and secret scanning.

Line, function, and branch coverage must each remain at least **96%**. The release-note checks require this fixed section order and a package table matching the current artifact inventory. Draft publication downloads all expected payloads and checksums, verifies them, and compares the downloaded bytes with the build outputs before making the release public.

UI previews use synthetic data and isolated/offscreen sessions. They do not claim testing with real provider credentials, consumption of banked resets, or installation over a running desktop plugin.
