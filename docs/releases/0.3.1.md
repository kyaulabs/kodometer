# 🚀 Kodometer 0.3.1

## ✨ Highlights

Kodometer 0.3.1 repairs the General settings page and panel tooltips introduced with the 0.3.0 presentation changes. The settings page starts at the top, scrolls to every provider, and keeps a visible scrollbar while its contents overflow. Panel tooltips no longer appear twice.

This is a patch release from 0.3.0, with one deliberate, owner-approved SemVer exception: independent donut colors are included alongside the fixes. That change is honestly recorded as `feat(ui)` and would normally require 0.4.0; the owner explicitly requested keeping it in 0.3.1. No breaking changes, credential migrations, polling changes, or provider API additions are included.

## 🚀 Features

In **Configure Kodometer… → General**, select **Donut charts** to enable **Session donut color** and **Weekly donut color**. Each picker controls only its own panel donut. The preview swatch shows the selected color; **Use meter accent** clears that donut's override.

Colors are saved per widget through **Apply**. Canceling the color picker leaves the staged setting unchanged; canceling the settings dialog restores saved choices. **Defaults** restores inherited Iris/Desktop accents. Switching back to bars preserves the saved donut colors but does not apply them to the bars. Existing widgets retain their current accent until a custom color is chosen.

## 🐛 Fixes

- General settings now use a scrolling page instead of an oversized bare form. The first controls remain reachable, the last provider can be reached by dragging the scrollbar, and resizing to fit returns the page to the top. Scrollbar visibility follows actual overflow rather than disappearing with the inactive style state.
- Bar mode uses one native Plasma tooltip titled **Kodometer**. It lists each provider's reported balance or remaining quota, rather than showing a second tooltip with cross-provider totals. DeepSeek, xAI, and OpenRouter show authoritative balances; Coding Plan providers prefer weekly quotas, then session or other available quota windows.
- Each donut has its own native tooltip: **Kodometer — Session quota** and **Kodometer — Weekly quota**. Only that quota kind appears, on horizontal and vertical panels. Balance-only providers do not enter these lists. The shared bar tooltip is suppressed in donut mode, and donut tooltips are inactive while the widget popup is open.
- Missing, non-finite, and nonnumeric values are not displayed as zero. Actual zero remains zero. Idle windows and pending navigation placeholders are excluded; account-context invalidation removes old values. Optional BigModel CN balance never replaces authoritative Coding Plan quota in the bar summary.

A synthetic bar-mode example:

```text
Kodometer
Codex: 75% weekly remaining
Kimi Code: 80% weekly remaining
DeepSeek Balance: $1.00
```

## 🛠️ Installation and upgrade

Download the matching package and checksum. Log out of Plasma before replacing a loaded plugin, install from a TTY or SSH session, then log back in. Run only the commands for your distribution:

```bash
# Arch Linux
sha256sum -c kodometer-0.3.1-1-x86_64.pkg.tar.zst.sha256
sudo pacman -U ./kodometer-0.3.1-1-x86_64.pkg.tar.zst

# Ubuntu 26.04 LTS
sha256sum -c kodometer_0.3.1-1ubuntu26.04_amd64.deb.sha256
sudo apt install ./kodometer_0.3.1-1ubuntu26.04_amd64.deb

# Fedora 43
sha256sum -c kodometer-0.3.1-1.fc43.x86_64.rpm.sha256
sudo dnf install ./kodometer-0.3.1-1.fc43.x86_64.rpm

# Fedora 44
sha256sum -c kodometer-0.3.1-1.fc44.x86_64.rpm.sha256
sudo dnf install ./kodometer-0.3.1-1.fc44.x86_64.rpm
```

Keep the same installation method and prefix. Remove duplicate manual system/user-local plugins before switching to a managed package. The applet ID remains `org.kyaulabs.kodometer`; existing preferences, OAuth files, and KWallet entries need no migration. Missing color preferences inherit the existing meter accent.

See the tagged [package guide](https://github.com/kyaulabs/kodometer/blob/v0.3.1/docs/packaging.md) and [source/user-local installation instructions](https://github.com/kyaulabs/kodometer/blob/v0.3.1/README.md#build-and-install). Package removal does not delete credentials or preferences; manual removal should use the generated install manifest while Plasma is stopped.

## ⚠️ Compatibility and known limitations

- Requires **KDE Plasma/libplasma 6.4+**, Qt 6.4+, and the documented Wallet/notification dependencies. Wayland and X11 remain supported.
- Binary targets remain Arch Linux, Ubuntu 26.04 LTS, and Fedora 43/44 on x64. Ubuntu 24.04, ARM binaries, generic Debian/RHEL compatibility, and hosted APT/DNF repositories are not included.
- The donuts still summarize the most constrained session and weekly quotas across providers; this is not one donut per provider. Their hover text identifies individual contributors. Providers without a matching quota kind are absent from that donut's tooltip.
- Custom colors are opaque RGB overrides, not automatic contrast adjustments. Choose colors that remain legible against your panel. Small panels may still lack room for donut-center percentages; tooltips retain the values.
- Provider authentication and service scope are unchanged. Kimi's website **Total usage** lane and reset redemption remain unsupported; xAI still covers developer billing, not Grok subscriptions. See the [provider requirements](https://github.com/kyaulabs/kodometer/blob/v0.3.1/README.md#requirements).

## 🔒 Security and privacy

Tooltips use fixed public provider names and normalized numeric usage as plain text. Saved account/profile names, private selectors, API error strings, and provider-supplied labels do not enter them. The tooltip and color controls add no credential access, provider requests, browser-session inspection, CLI execution, or billing persistence.

Only nonsecret RGB strings are added to per-widget Plasma configuration. Credentials and private selectors remain in KWallet or their originating provider-owned OAuth files. Named selections remain exclusive and selected-only. Invalid saved color strings fall back to the normal accent.

Checksums detect corruption, not publisher identity. Release tags are annotated but not independently GPG-signed by this workflow; DEB/RPM artifacts are not independently signed either. Published assets are immutable. See the [security contract](https://github.com/kyaulabs/kodometer/blob/v0.3.1/README.md#security-and-privacy).

## ✅ Validation

The changes have regression tests for initial scroll position, visible scrollbar geometry and dragging, bottom-control reachability, resize recovery, bar summaries, separate horizontal/vertical donut hover areas, malformed and missing data, Coding Plan precedence, picker accept/cancel/reset, independent colors, compiled configuration resources, and KConfig persistence.

Publication requires native Debug tests, QML and source-format checks, Python automation tests, commit/workflow/dependency/security checks, and fresh Release builds with clean-runtime install/reinstall/launch checks for all four distributions. Line, function, and branch coverage gates remain at least **96%**. The publisher verifies the complete draft inventory, downloads every asset, checks its hashes, and compares bytes with the build outputs before making the release public.

Rendered previews use synthetic usage in isolated/offscreen sessions. They verify settings and tooltip presentation without replacing the running desktop plugin, reading real provider credentials, or consuming quota.
