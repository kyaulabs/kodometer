# 🚀 Kodometer 0.4.0

## ✨ Highlights

Kodometer 0.4.0 replaces cross-provider quota donuts with provider-specific nested rings, adapts popup height to the selected tab, and adds persistent observed subscription-quota history. It follows 0.3.1 with a minor bump: the reviewed `feat: add provider quota views and persistent history` commit makes `git-cliff --bumped-version --use-branch-tags` select `v0.4.0`.

There is no credential or account migration and no new runtime dependency. Two presentation defaults change deliberately: Codex Spark is hidden, and popup bars fill with remaining quota. Both can be changed in General settings. Existing provider selections and custom Session/Weekly ring colors are retained.

## 🚀 Features

- **Provider-specific donuts:** donut mode shows one meter for each provider with valid quota windows. Its enabled windows become differently colored nested rings; hover text names only that provider's windows, remaining percentages, and ring positions. Balance-only and pending selections do not become quota donuts. The existing compact bar mode remains available.
- **Consistent window controls:** General settings lists reported quota windows. Switches affect Overview, provider rows, rings, tooltips, and visible history series. Spark and idle windows also require their respective display switches. These are presentation controls, not changes to notification policy or provider polling.
- **Adaptive popup:** the wordmark has balanced layout spacing. Width stays stable while preferred height follows the selected page, capped at 85% of screen height; long content scrolls.
- **Remaining-quota bars:** thicker bars use a neutral track and subtle corners. A value such as 65% left fills 65% of the bar by default. Disable the remaining-quota setting to fill with used quota instead.
- **Observed quota history:** Codex, Claude, Gemini, Kimi Code, and z.ai quota views offer provider-colored 24-hour, 7-day, and 30-day charts. They record normal successful refreshes, not extra requests or reconstructed past activity. Invalid/idle values and monetary spending caps are not recorded. Lines break at resets, increases in remaining quota, and gaps longer than 15 minutes.
- **Confirmed clearing:** the popup footer can clear saved quota history even when no provider data is available. Chart buttons offer the same confirmed action. Clearing removes observations across providers, profiles, and accounts, not credentials or preferences.

## 🐛 Fixes

- Different providers no longer share a misleading pair of Session/Weekly donuts. Tooltips match the hovered provider, and pending account-navigation placeholders cannot supply its quotas.
- Switching between short balance views and longer quota views no longer leaves the popup at one fixed preferred height.
- Replacing effective Default wallet credentials invalidates the affected provider's old snapshots, errors, and history view before pending replies can publish. A wallet edit that changes no selected credential context does not schedule a refresh; matching environment precedence remains intact.
- External credential replacements cannot expose the previous identity's history, including when the new response has no usable quotas. Trusted OAuth rotations keep the current identity pinned and can merge linked observations recorded by multiple widgets.
- History clearing is safe during update callbacks. Failed filesystem metadata checks, synchronization, or replacement preserve the existing file and report a storage warning without hiding current provider usage.

## 🛠️ Installation and upgrade

Download the matching package and checksum from this release. **Log out of Plasma before replacing the loaded plugin**, install from a TTY or SSH session, then log back in. Do not overwrite a library used by the running desktop.

```sh
# Arch Linux
sha256sum -c kodometer-0.4.0-1-x86_64.pkg.tar.zst.sha256
sudo pacman -U ./kodometer-0.4.0-1-x86_64.pkg.tar.zst

# Ubuntu 26.04 LTS
sha256sum -c kodometer_0.4.0-1ubuntu26.04_amd64.deb.sha256
sudo apt install ./kodometer_0.4.0-1ubuntu26.04_amd64.deb

# Fedora 43
sha256sum -c kodometer-0.4.0-1.fc43.x86_64.rpm.sha256
sudo dnf install ./kodometer-0.4.0-1.fc43.x86_64.rpm

# Fedora 44
sha256sum -c kodometer-0.4.0-1.fc44.x86_64.rpm.sha256
sudo dnf install ./kodometer-0.4.0-1.fc44.x86_64.rpm
```

Keep one installation method and prefix. Remove manual system or user-local plugin copies before switching to a native package; otherwise Qt can load an older duplicate. Credentials and existing preferences need no migration. New quota observations are collected after successful refreshes. Packages do not delete credentials, preferences, or the user-owned history file on removal; use the widget's clear action to remove history explicitly.

See the [0.4.0 package guide](https://github.com/kyaulabs/kodometer/blob/v0.4.0/docs/packaging.md) for source/AUR recipes and the [tagged build instructions](https://github.com/kyaulabs/kodometer/blob/v0.4.0/README.md#build-and-install) for prefix-sensitive manual installation. Container provisioning scripts are not desktop installers.

## ⚠️ Compatibility and known limitations

- The compiled applet requires **Plasma/libplasma 6.4+**, Qt 6, and KDE Frameworks 6. CMake declares Qt 6.4 as its minimum; use the compatible, newer Qt/KDE stack supplied by a supported distribution. The validated binary targets are Arch rolling, Ubuntu 26.04 LTS, and Fedora 43/44 on x64. There are no ARM, generic Debian, or RHEL packages. Ubuntu 24.04's standard Plasma stack is too old.
- Native packages are distribution/ABI-specific. There is no hosted APT/DNF repository or automatic desktop updater. Compiled applets are not `kpackagetool6` ZIPs.
- History keeps the latest actual observation per five-minute bucket. Pruning occurs during recording, not through a background cleanup service: inactive files can remain until a later refresh or explicit clear. Limits of 64 partitions, 32 windows per partition, 64,000 observations, and 8 MiB can shorten retained history. Thirty days is not a promise of complete data.
- Stored history is restored only after a successful refresh with the matching profile/account and authenticated identity. External login/key changes may start a separate history. Other widgets reload shared storage on their next successful refresh after a clear.
- Polling only selected accounts, missing-selection behavior, and native authentication restrictions are unchanged. Gemini history is Code Assist OAuth quota, not API-key/Vertex support; Kimi is For Coding, not Moonshot; xAI is Management API billing, not Grok subscriptions. Spending/billing history remains transient. See the [tagged provider contract](https://github.com/kyaulabs/kodometer/blob/v0.4.0/README.md).

## 🔒 Security and privacy

Observed quotas use owner-only `$XDG_DATA_HOME/kodometer-quota-history/history.json`, normally under `~/.local/share`. Storage uses ownership/type/mode/link checks, bounded reads, no-follow descriptor-relative operations, a nonblocking directory lock, and atomic replacement. Only opaque partition digests, public window kinds, timestamps, remaining percentages, and reset timestamps are serialized. Keys, tokens, private selectors, account labels, and credential paths are not copied into history.

Manual secrets and private selectors remain in KWallet. OAuth renewal stays pinned to the originating provider-owned file. There are no provider CLI executions, browser-session reads, extra history requests, or Qt Charts dependency. Notifications remain off by default and consume fresh results independently of presentation switches.

Published assets are immutable. SHA-256 files detect corruption; they do not establish publisher identity. The workflow creates an annotated source tag, not an independently GPG-signed tag, and does not independently sign DEB/RPM payloads. Reviewed development commits retain their GPG signatures through merge commits.
