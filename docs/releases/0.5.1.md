# 🚀 Kodometer 0.5.1

## ✨ Highlights

Kodometer 0.5.1 polishes the controls and colors introduced in 0.5.0. Footer icons have matching sizes, Overview uses the logo's neutral accent, Codex Spark has one toggle, and donut colors come only from provider settings.

This is a patch release after 0.5.0. The reviewed `fix: unify provider colors and simplify display controls` commit makes `git-cliff --bumped-version --use-branch-tags` select `v0.5.1`; no feature commits or public API changes are included. No credential, account, or history migration is required. Removing obsolete color controls and ignoring their saved overrides are deliberate presentation changes described below.

## 🚀 Features

No new features or runtime dependencies. Per-provider color settings, content-sized popup pages, selected-account polling, and observed quota history remain available as introduced in earlier releases.

## 🐛 Fixes

- **Matching footer icons:** settings now uses a symbolic action icon rather than a potentially oversized full-color toolbox. Settings, clear-history, and refresh icons have the same explicit dimensions.
- **Neutral Overview accent:** the Overview tab uses brand Cloud `#F7F5FB` on dark surfaces, matching the logo's off-white lettering. On light surfaces it uses brand Ink `#252333` for visibility. Provider tabs retain their own accents.
- **One Spark toggle:** **Show Codex Spark quota** controls all Codex Spark windows and remains off by default. Duplicate Spark-window controls are removed from General settings. Obsolete per-window Spark hiding entries no longer prevent the master switch from enabling Spark. Idle Spark windows still require **Show idle quota windows**; notification policy and recording are unchanged.
- **One source for chart colors:** the old **Session donut color** and **Weekly donut color** controls are removed. Their saved keys remain inert compatibility data and no longer override provider accents. Inner rings continue to derive distinct colors from the provider color. Use **General → Providers → Choose color…** or **Use default color**; Apply/Cancel/Defaults behavior is unchanged.
- **Corrected provider defaults:** Codex defaults to Iris `#A28BE0`, Kimi Code to teal `#49A3B0`, and OpenRouter to lime `#C8FF00`. Settings previews and native provider presentation agree. Existing custom provider colors are preserved; select **Use default color** and Apply to adopt a new default.
- **Stable page transitions:** a shrinking page list now clamps selection against the current array rather than a stale derived count, preventing transient undefined-page QML errors during layout changes.

## 🛠️ Installation and upgrade

Download the matching native package and its checksum. **Log out of Plasma before replacing the loaded plugin**, install from a TTY or SSH session, then log back in.

```sh
# Arch Linux
sha256sum -c kodometer-0.5.1-1-x86_64.pkg.tar.zst.sha256
sudo pacman -U ./kodometer-0.5.1-1-x86_64.pkg.tar.zst

# Ubuntu 26.04 LTS
sha256sum -c kodometer_0.5.1-1ubuntu26.04_amd64.deb.sha256
sudo apt install ./kodometer_0.5.1-1ubuntu26.04_amd64.deb

# Fedora 43
sha256sum -c kodometer-0.5.1-1.fc43.x86_64.rpm.sha256
sudo dnf install ./kodometer-0.5.1-1.fc43.x86_64.rpm

# Fedora 44
sha256sum -c kodometer-0.5.1-1.fc44.x86_64.rpm.sha256
sudo dnf install ./kodometer-0.5.1-1.fc44.x86_64.rpm
```

Keep one installation method and prefix. Remove manual system or user-local duplicates before switching to a native package, so Qt cannot load an older copy. Existing credentials, selections, custom provider colors, and quota observations need no migration. Old Session/Weekly colors stop applying, and the master Spark setting supersedes old Spark-window exclusions without rewriting them.

See the [0.5.1 package guide](https://github.com/kyaulabs/kodometer/blob/v0.5.1/docs/packaging.md) and [tagged build instructions](https://github.com/kyaulabs/kodometer/blob/v0.5.1/README.md#build-and-install) for source recipes and prefix-sensitive installation. Container provisioning helpers are not desktop installers. Package removal does not delete credentials, preferences, or the user-owned history file.

## ⚠️ Compatibility and known limitations

- The compiled applet requires **Plasma/libplasma 6.4+**, Qt 6.4+, and KDE Frameworks 6. Use the compatible Qt/KDE stack supplied by Arch rolling, Ubuntu 26.04 LTS, or Fedora 43/44. Release binaries are x64 only; there are no ARM, generic Debian, or RHEL packages. Ubuntu 24.04's standard Plasma stack is too old.
- Packages are distribution/ABI-specific. There is no hosted APT/DNF repository or automatic desktop updater. Compiled applets are not `kpackagetool6` ZIPs.
- Theme-provided symbolic artwork can differ, but footer icon dimensions are consistent. Provider colors do not recolor logos or semantic notification states. Nested rings use derived window colors, not identical colors for every ring.
- Settings dialogs can still scroll. Popup content uses numbered inner pages when it exceeds the screen budget; exceptionally tall sections can continue across pages. Provider navigation can scroll horizontally.
- Provider/authentication and history limits are unchanged. Only selected accounts are polled. Gemini remains Code Assist OAuth quota, Kimi is For Coding rather than Moonshot, and xAI is Management API billing rather than Grok subscriptions. See the [tagged provider contract](https://github.com/kyaulabs/kodometer/blob/v0.5.1/README.md).

## 🔒 Security and privacy

No authentication endpoints, credential handling, polling, notification policy, or history-storage rules change. Color and window preferences are nonsecret per-widget presentation settings. Manual secrets and private selectors remain in KWallet; OAuth renewal stays pinned to its originating provider-owned file. There are no provider CLI executions, browser-session reads, or additional network requests.

The single history-clear icon still requires confirmation and removes observations across providers, profiles, and accounts, not credentials, preferences, or provider-reported billing history. Packages never remove those user-owned files.

Published assets are immutable. SHA-256 files detect corruption but do not establish publisher identity. The workflow creates an annotated source tag, not an independently GPG-signed tag, and does not independently sign DEB/RPM payloads. Reviewed development commits retain their GPG signatures through merge commits.
