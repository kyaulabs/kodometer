# 🚀 Kodometer 0.6.1

## ✨ Highlights

Kodometer 0.6.1 restores the Arch package after the Plasma 6.8 library ABI change. Plasma 6.8 supplies `libPlasma.so.8`, while the previous Arch binary required `libPlasma.so.7`. That mismatch prevented the applet from loading and could also produce a misleading missing-metadata error.

This is a patch release after 0.6.0. The `fix(packaging)` commits correct binary dependencies, AUR source metadata, and test isolation; there are no new features or breaking source/API changes. `git-cliff --bumped-version` selects `v0.6.1`. Credentials, preferences, selected accounts, and quota-history files need no migration.

## 🚀 Features

No new widget features or settings. Provider requests, selected-account polling, notifications, charts, and presentation are unchanged from 0.6.0. Source builds retain the Plasma 6.4 minimum and can target either older supported libraries or Plasma 6.8.

## 🐛 Fixes

- The rolling Arch payload is rebuilt against Plasma 6.8's `libPlasma.so.8`. Other native packages continue to build against their own distribution's libraries, not the Arch binary.
- Arch binary packages now require the Plasma minor series used for their build. A 6.8 build requires `libplasma>=6.8` and `libplasma<6.9`. This conservative bound prevents a later minor-series upgrade from silently leaving an unloadable plugin, while permitting patch updates. It does not rebuild Kodometer automatically.
- The source recipe remains usable on older supported Plasma releases, including `libPlasma.so.7` systems. Rebuilding produces a binary for that system's libraries and records its own series bounds. A single compiled plugin does not support both SONAMEs.
- AUR `.SRCINFO` retains only the Plasma 6.4 source minimum. Build-only dependency bounds run outside makepkg's static source-metadata extraction, preventing empty version components in the recipe bundle. Native Arch packaging now checks the real generated `.SRCINFO` before building or uploading recipes.
- Offscreen QML tests no longer activate Qt desktop portals. On newer Qt, a document-portal mount could outlive the private test session and make temporary-directory cleanup fail even when every UI assertion passed. This change affects tests only.

## 🛠️ Installation and upgrade

Download the package and checksum for your distribution from this release. Log out of Plasma before replacing its loaded plugin; install from a TTY or SSH session, then log back in.

```sh
# Arch Linux with Plasma 6.8
sha256sum -c kodometer-0.6.1-1-x86_64.pkg.tar.zst.sha256
sudo pacman -U ./kodometer-0.6.1-1-x86_64.pkg.tar.zst

# Ubuntu 26.04 LTS
sha256sum -c kodometer_0.6.1-1ubuntu26.04_amd64.deb.sha256
sudo apt install ./kodometer_0.6.1-1ubuntu26.04_amd64.deb

# Fedora 43
sha256sum -c kodometer-0.6.1-1.fc43.x86_64.rpm.sha256
sudo dnf install ./kodometer-0.6.1-1.fc43.x86_64.rpm

# Fedora 44
sha256sum -c kodometer-0.6.1-1.fc44.x86_64.rpm.sha256
sudo dnf install ./kodometer-0.6.1-1.fc44.x86_64.rpm
```

On an older Arch Plasma series, verify and review the release's source recipes, then build with `makepkg -s` as a normal user against that system's installed development packages. Build before logging out; install the resulting package with `sudo pacman -U` from a TTY or SSH session while Plasma is stopped. Rebuild again when changing Plasma minor series if no matching binary package is available. Do not force an incompatible package installation or symlink `.7` to `.8`.

Keep the same installation method and prefix. Remove manual system or user-local duplicates before switching to a native package. Do not overwrite a package-managed plugin with `cmake --install`. Preferences, credentials, account selections, and recorded quota history are not installation payloads and are not deleted on package removal. There is no credential reset or data migration for this fix.

See the [0.6.1 package guide](https://github.com/kyaulabs/kodometer/blob/v0.6.1/docs/packaging.md) and [tagged source-build instructions](https://github.com/kyaulabs/kodometer/blob/v0.6.1/README.md#build-and-install). Container provisioning helpers are not desktop installers; compiled applets are not `kpackagetool6` ZIPs.

## ⚠️ Compatibility and known limitations

- Plasma/libplasma 6.4+, Qt 6.4+, and KDE Frameworks 6 remain required for source builds. Source compatibility is not cross-ABI binary compatibility. Each binary must match its distribution's installed Qt/KDE libraries; none are bundled.
- The Arch binary targets the current rolling Plasma 6.8 series. Older Arch Plasma systems must build from source rather than use that binary. Minor-series bounds are deliberately conservative because Arch's libplasma package does not advertise a SONAME dependency; even an ABI-compatible future minor update requires a matching rebuild.
- Released native targets remain Arch rolling, Ubuntu 26.04 LTS, and Fedora 43/44 on x64. There are no ARM, generic Debian, or RHEL packages. Ubuntu 24.04's standard Plasma stack is too old. No APT/DNF repository or automatic desktop updater is provided.
- Provider restrictions are unchanged: Gemini is Code Assist OAuth quota, Kimi is For Coding rather than Moonshot, and xAI is developer Management API billing rather than Grok subscriptions. See the [tagged provider contract](https://github.com/kyaulabs/kodometer/blob/v0.6.1/README.md).

## 🔒 Security and privacy

No authentication endpoint, credential discovery, KWallet storage, request policy, notification rule, or history format changes. Provider CLIs and browser sessions are not used. OAuth renewal remains pinned to its originating provider-owned file; private selectors and manually saved keys remain in KWallet.

The portal change is confined to private offscreen tests and does not disable desktop portals in the installed widget. Validation uses synthetic credentials and isolated sessions, not the user's desktop or real provider accounts.

Published assets remain immutable. SHA-256 files detect corruption but do not establish publisher identity. The publication workflow creates an annotated source tag, not an independently GPG-signed tag, and does not independently sign DEB/RPM payloads. Reviewed development commits retain their GPG signatures through merge commits.

## ✅ Validation

The compatibility fix passed all 40 CTest entries in a Plasma 6.8.1 Debug build and in fresh Release builds for both ABIs. ABI-7 testing used a signature-verified Arch libplasma 6.7.5 SDK extracted into a temporary prefix, not an older live desktop. `readelf` confirmed `.7` and `.8` linkage respectively, and `ldd -r` reported no missing libraries or undefined symbols. An isolated `plasmawindowed` smoke test loaded the rebuilt `.8` plugin without replacing the installed desktop plugin.

All 47 offline Python tests passed, including regression cases that failed before the dependency-bound fix. The isolated coverage build passed 37 tests with 98.9% line, 100% function, and 96.2% branch coverage, above all three unchanged 96% gates. QML lint, formatting, ShellCheck, Actionlint, commitlint, signature verification, and Gitleaks passed. The fix PR passed all 15 CI checks, including dependency review, four native Release builds, four separate clean-runtime install/reinstall tests, and inventory verification. Its downloaded candidate bundle passed checksum verification; the Arch package declared the expected 6.8-series bounds and linked `.8`. Later candidate inspection found malformed AUR source-only dependency bounds despite green CI. That defect was corrected before publication, and the Arch job now validates real makepkg source metadata as well as binary packaging.
