# 🚀 Kodometer 0.7.0

## ✨ Highlights

Kodometer 0.7.0 brings subscription quotas and OpenAI API Platform spending together under the OpenAI provider. The former Codex entry is renamed throughout the widget and native implementation. Existing provider preferences, selected credential profiles, and authenticated quota history migrate without a credential reset. A separate organization Admin API key enables API spending; subscription credentials are not reused for billing.

This is a minor release after 0.6.1. The `feat(openai)` commit adds API spending and configurable Plan/API presentation, while `fix(openai)` and `fix(deps)` commits improve response validation and address four development-tool security advisories. `git-cliff --bumped-version` selects `v0.7.0`. There is no deliberate breaking widget configuration or authentication change: legacy profile keys remain accepted at the storage boundary, and existing selections and colors are preserved. Internal C++ types and provider IDs are renamed; the applet does not offer those types as a stable external SDK.

## 🚀 Features

- **OpenAI provider:** the former Codex provider now appears as OpenAI in settings, navigation, notifications, and quota presentation. External `CODEX_HOME`, `~/.codex/auth.json`, OAuth protocols, and official Codex URLs remain unchanged. Existing subscription collection and secure token rotation continue to work with the selected credential folder.
- **API Platform spending:** store an **OpenAI organization Admin API key** under **Configure Kodometer… → Credentials**, or export `OPENAI_ADMIN_KEY` before starting Plasma. Nonempty matching environment credentials retain precedence over KWallet. The official organization Costs endpoint supplies reported daily USD spending, month-to-date totals, and 7-day/30-day spending charts. Ordinary project API keys and Codex OAuth credentials do not provide organization Costs access.
- **Plan/API presentation:** **Show OpenAI Plan and API in separate tabs** is enabled by default in General settings. Turn it off to stack plan quotas/history and API spending on the same provider page. Subscription credits and quota percentages are not shown as API credit balances. An API-only setup can display spending without a working plan login.
- **Independent contexts:** changing the selected plan profile does not replace the API Admin key or invalidate its retained spending. Changing that key clears only the API context. Disabling OpenAI excludes both request paths from polling. API spending charts add no background billing-history persistence or chart-specific requests.

Actual prepaid credit balance is not exposed by the supported public API. The API view explicitly marks it unavailable; reported spending is not presented as a remaining balance or necessarily as a prepaid-credit deduction. No dashboard scraping, browser-session access, manual credit ledger, or inferred balance is introduced.

## 🐛 Fixes

- Legacy Codex provider switches, provider-color overrides, Spark preferences, and hidden-window keys migrate to OpenAI. Named OAuth profile selections remain exclusive rather than falling back to Default. Ambiguous duplicate old/new profile registries fail closed.
- Existing quota-history partitions move into the OpenAI namespace only after a successful refresh matches the original credential/profile context and authenticated identity. An unrelated login cannot restore another account's observations.
- Costs parsing rejects malformed, duplicate, unsupported-currency, oversized, and paginated partial responses instead of publishing plausible partial totals. The final current-day bucket may end at the pinned request time; clipped bounds on older days remain invalid. Unreported days and unreported totals remain unknown, not zero.
- API-only results retain other providers' ordering and cannot replace their presentation data. The normal no-overlap, bounded-timeout, redirect-disabled request policy remains in force.
- Development-only `fast-uri` is updated from 3.1.7 to 3.1.9 through Ajv and Commitlint, addressing all four open advisories. Direct tooling versions and native runtime dependencies are unchanged.

## 🛠️ Installation and upgrade

Download the package and checksum for your distribution from this release. Log out of Plasma before replacing a loaded plugin, install from a TTY or SSH session, and log back in afterward.

```sh
# Arch Linux (rolling), matching the package's Plasma minor-series bounds
sha256sum -c kodometer-0.7.0-1-x86_64.pkg.tar.zst.sha256
sudo pacman -U ./kodometer-0.7.0-1-x86_64.pkg.tar.zst

# Ubuntu 26.04 LTS
sha256sum -c kodometer_0.7.0-1ubuntu26.04_amd64.deb.sha256
sudo apt install ./kodometer_0.7.0-1ubuntu26.04_amd64.deb

# Fedora 43
sha256sum -c kodometer-0.7.0-1.fc43.x86_64.rpm.sha256
sudo dnf install ./kodometer-0.7.0-1.fc43.x86_64.rpm

# Fedora 44
sha256sum -c kodometer-0.7.0-1.fc44.x86_64.rpm.sha256
sudo dnf install ./kodometer-0.7.0-1.fc44.x86_64.rpm
```

Keep the same installation method and prefix. Remove manual system or user-local duplicates before switching to a native package, and do not overwrite a package-managed plugin with `cmake --install`. Package removal does not delete credentials, wallet entries, preferences, or quota history. Preferences and history migrate when the upgraded widget runs; credential files are not renamed or copied. There is no need to sign in again solely for the rename. API spending is separate and requires configuring its Admin key.

For an older compatible Plasma series, verify and review the source recipe bundle, then build as a normal user against that system's libraries. Build before logging out and install the resulting package while Plasma is stopped. Rebuild for a different Plasma minor series if no matching binary package exists. Never force incompatible library dependencies or symlink different Plasma SONAMEs together.

See the [0.7.0 package guide](https://github.com/kyaulabs/kodometer/blob/v0.7.0/docs/packaging.md) and [tagged source-build instructions](https://github.com/kyaulabs/kodometer/blob/v0.7.0/README.md#build-and-install). Container provisioning helpers are not desktop installers, and compiled applets are not `kpackagetool6` ZIPs.

## ⚠️ Compatibility and known limitations

- Source builds require Plasma/libplasma 6.4+, Qt 6.4+, and KDE Frameworks 6. Binary packages must match their distribution's installed Qt/KDE libraries. Arch binaries retain conservative bounds to the Plasma minor series used for their build; one plugin does not span incompatible library SONAMEs. No Qt/KDE libraries are bundled.
- Native release targets remain Arch rolling, Ubuntu 26.04 LTS, and Fedora 43/44 on x64. There are no ARM, generic Debian, or RHEL packages. Ubuntu 24.04's standard Plasma stack is too old. No hosted APT/DNF repository or automatic desktop updater is provided.
- OpenAI API spending is organization-wide and requires an Admin API key authorized for Costs. This release does not add a project filter or named API organization accounts. Billing data may be delayed. Missing daily reports remain unknown, and current-month/current-day totals represent reported data rather than a final invoice.
- Renaming the existing subscription integration does not add unsupported ChatGPT model quotas. Its provider-owned Codex credential/protocol contract remains unchanged. An ordinary file API key accepted by that integration is not an organization billing credential.
- Gemini remains Code Assist OAuth quota, Kimi remains For Coding rather than Moonshot, and xAI remains developer Management API billing rather than Grok subscriptions. See the [tagged provider contract](https://github.com/kyaulabs/kodometer/blob/v0.7.0/README.md).

## 🔒 Security and privacy

The `fast-uri` update addresses GHSA-xhq7-xmqj-769h, GHSA-w74x-v6f9-j3xg, GHSA-333x-w4r6-6crp, and GHSA-wjr9-j795-jxcr in the development-tool dependency graph. The fixed lockfile reaches the default `main` branch through this release rather than dismissing the associated alerts. `pnpm audit` reports no known vulnerabilities in the prepared dependency graph.

The new Admin key stays in KWallet or the process environment and is not copied into Plasma settings, QML metadata, logs, notifications, browser URLs, or plan credential files. API requests use the fixed official HTTPS endpoint, reject redirects, and bound time and response size. Plan credentials and OAuth renewal remain pinned to the originating secure file. Browser sessions and provider CLIs are not used. API billing history remains transient; subscription quota history retains its bounded, owner-only storage and authenticated restore rules.

Published assets remain immutable. SHA-256 files detect corruption but do not establish publisher identity. Publication creates an annotated source tag, not an independently GPG-signed tag, and does not independently sign DEB/RPM payloads. Reviewed development commits retain their GPG signatures through merge commits.
